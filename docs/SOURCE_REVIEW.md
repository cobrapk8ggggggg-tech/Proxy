## أهم مشاكل التنفيذ القديم التي عولجت

- تجزئة بادئة التوكن كانت تسمح بتصادم حسابين؛ تُستخدم بصمة التوكن كاملًا.
- ربط المحادثات بأول system prompt كان يدمج محادثات مستقلة؛ أصبح الربط بتاريخ المحادثة الكامل ضمن العميل والحساب والمشروع.
- إزالة الطلبات المتشابهة عالميًا كانت تمنع بدء محادثتين متطابقتين؛ أُزيلت، وأُضيف idempotency صريح من العميل.
- معرف SSE كان يتغير بين الأجزاء؛ أصبح ثابتًا.
- استخراج tool arguments بتعبير منتظم قصير كان يفسد JSON المتداخل؛ أصبح تحليل JSON حقيقيًا مع التحقق من المخطط.
- تنظيف كلمة ACTION من رد عادي كان يغيّر نص المستخدم؛ لا يُفسّر كأداة إلا عند تحقق صيغة استدعاء الأداة.
- الرجوع إلى Qwen عند اسم نموذج مجهول كان يرسل الطلب إلى حساب آخر؛ الاسم المجهول يعيد 404.
- أخطاء الشبكة والمزوّد والردود الناقصة لا تُقدَّم كإجابات ناجحة.
- مصادقة Gemini تتحقق من TLS وتبقى على الحساب المقدم؛ لا سقوط صامت إلى ضيف ولا تسجيل CSRF أو الكوكيز.
- تبديل توكن الحساب يمسح الربط السابق ويعزل ذاكرة الطلبات المكررة عن بيانات الدخول الجديدة.
- صُححت صيغة `proxy=` في HTTPX بدل `proxies=` القديمة، وأُزيل مسار DeepSeek القديم الذي يضع التوكن في عنوان URL.

## بنية التنفيذ

| الملف | المسؤولية |
| --- | --- |
| `proxy/providers.py` | ChatGPT وGemini وWorker وطبقة Qwen، اكتشاف القوائم وتوليد الرد ورفع الملفات |
| `proxy/legacy_qwen.py` | مساعدات Qwen الأصلية بعد إصلاحها؛ لا يستورد الخادم القديم كاملًا |
| `proxy/store.py` | SQLite وخزنة الحسابات المشفرة والمفاتيح والحالة |
| `proxy/engine.py` | ربط المحادثات والأقفال واختيار المسار ومعالجة المرفقات |
| `proxy/protocol.py` | تحويل Chat وResponses وSSE والأدوات |
| `proxy/chatgpt_models.py` | فئات نماذج الحساب وAuto وفصل الدردشة عن العمل والبحث |
| `proxy/translation.py` | الوضع الاختياري لترجمة فقرات Gemini |
| `proxy/app.py` | API العميل والإدارة والمصادقة والحدود |
| `static/` | اللوحة العربية دون مكتبات واجهة خارجية أو build مطلوب |
| `tests/` | اختبارات البروتوكولات والعقد وSDK والواجهة |

تغييرات مشروع الروايات السابق منفصلة عن هذا التسليم. هذا المستودع بروكسي جديد قابل للاستضافة، ولا يحتاج ربطه بموقع الروايات أو تغيير خادمه لتشغيله.

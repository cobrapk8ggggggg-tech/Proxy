# بيئة التطبيق وبيئة ChatGPT

OpenMinis ينفّذ `shell_execute` في iSH/Alpine على الهاتف. بعض نماذج حساب ChatGPT تملك أدوات داخلية تعمل في بيئة أخرى. تسمية البيئتين «Linux» لا تجعلهما بيئة واحدة، وملف `/root/...` في إحداهما لا يشير إلى ملف الأخرى.

من **إدارة الحساب ← بيئة أدوات الوكيل**، أو من إعدادات مسار النموذج، اختر:

| الخيار | السلوك عند إرسال التطبيق أدواته |
| --- | --- |
| أدوات التطبيق فقط · OpenMinis | الافتراضي. تعليمات تطلب JSON لاستدعاء أدوات التطبيق وانتظار النتائج الفعلية. إذا رصد تدفق ChatGPT أداة داخلية في رد مكتمل، يُرسل توجيه تصحيحي منفصل مرة واحدة لطلب أداة التطبيق. عند استمرار المخالفة يُعاد خطأ، دون اختلاق استدعاء أو نتيجة. لا تُعاد طلبات الشبكة المنقطعة تلقائيًا. |
| البيئتان · التطبيق وChatGPT | يسمح للنموذج بالعمل الداخلي المستقل، ثم طلب أدوات التطبيق أيضًا. لا يضيف البروكسي أي تنبيه نصي مع استدعاء الأداة. معلومات الرصد تبقى في حقل execution فقط. |

الإعداد اسمه `tool_environment` وقيمته `application` أو `hybrid`. لا يحتاج المستخدم معرفات أو إعدادات Linux إضافية. لا يغير هذا الإعداد قائمة نماذج الحساب أو اختيار المشروع؛ ولا يقيّد أدوات الدردشة الأصلية عندما لا يرسل العميل أدوات. لا يستطيع طلب العميل تجاوز سياسة الحساب أو المسار. `tool_choice=none` يمنع طلب أدوات التطبيق؛ في وضع البيئتين تبقى أدوات ChatGPT الداخلية مسموحة.

ابدأ محادثة تطبيق جديدة بعد التغيير. يعزل البروكسي سياق المحادثات التلقائية حسب السياسة، لكن المحادثة الثابتة المختارة عمدًا تبقى نفس المحادثة الأصلية؛ اختر محادثة أخرى إذا أردت إزالة سياقها السابق.

## كيف نجمع البيئتين؟

مثال طلب: «احسب التجزئة داخل Python لدى ChatGPT، ثم استخدم shell_execute لقراءة الملف من بيئة التطبيق، واعرض كل نتيجة مع اسم بيئتها». ينجز النموذج العمل الداخلي إن كانت أدوات الحساب تدعمه، ثم يعيد JSON يترجمه البروكسي إلى OpenAI `tool_calls`. ينفذ OpenMinis الأداة ويعيد `role:tool` مع `tool_call_id`، وبعدها يكمل النموذج.

لا ينفّذ البروكسي أوامر الوكيل محليًا. لا تنتقل الملفات أو العمليات أو الحزم تلقائيًا بين الهاتف وChatGPT. نقل ملف يحتاج بياناته الفعلية واستدعاء أداة تطبيق مناسبًا؛ روابط ملفات ChatGPT الداخلية ليست ملفات محلية في OpenMinis. نجاح عمليات نقل الملفات عمومًا لم يُختبَر هنا.

الأدوات الخارجية هنا جسر نصي فوق واجهة حساب ChatGPT، وليست تسجيل أدوات أصلية في API الرسمي. يستطيع النموذج مخالفة التعليمات، أو رفض طلب، أو اختيار بيئة غير مناسبة. الحماية ترصد أحداث الأدوات الداخلية التي تعرضها الخدمة؛ لا تضمن منع تنفيذ بدأ بالفعل في خدمة ChatGPT، ولا تكشف تنفيذًا لم يظهر في التدفق. لا تُعاد المحاولة تلقائيًا لتجنب تكرار العمل. للتنفيذ الخارجي الأكثر موثوقية، يظل API يدعم function calling أصليًا أفضل من محاكاة أدوات فوق واجهة حساب.

تحتوي استجابة JSON على حقل إضافي اختياري `execution` يبين السياسة ورصد الأدوات الداخلية وعدد استدعاءات التطبيق المطلوبة. تبقى استدعاءات أدوات OpenAI وSSE وResponses بصيغتها المعتادة. لا يعرض البروكسي التحليل الداخلي أو مخرجات الأدوات الداخلية الخام.

## أدلة الاختبار

بتاريخ 2026-10-19 استُخدم توكن الحساب المجاني المقدم للاختبار فقط:

- قبل التغيير رفض النموذج استدعاء shell_execute قائلًا إنها غير متاحة له.
- بعد التغيير نجحت دورة طلب أداة ← قراءة فعلية لملف يحوي قيمة عشوائية غير معروفة للنموذج ← نتيجة أداة ← جواب يتضمن القيمة الصحيحة، في وضع التطبيق ووضع البيئتين.
- في محاولة أخرى لوضع التطبيق طلب النموذج أداة داخلية رغم التعليمات؛ رصدها البروكسي وأعاد خطأ واضحًا بدل احتسابها تنفيذًا في التطبيق. لا تعني النجاحات التالية اختفاء هذا الاحتمال.
- نجح اختبار يجمع حساب تجزئة SHA256 تكراريًا 100003 مرة في أدوات ChatGPT الداخلية وقراءة الملف في عميل منفصل؛ طابقت النتيجتان القيم المتوقعة.
- شملت دورة HTTP المحلية الفعلية خروج `tool_calls` وعودة النتيجة عبر SSE. عميل الاختبار قرأ ملفًا معروفًا فقط، ولم ينفّذ أوامر shell عشوائية. لم يُشغَّل تطبيق iPhone الأصلي على هاتف فعلي.

التقرير المنقح في [live-tool-environments.json](live-tool-environments.json). إعادة الاختبار الاختياري تتطلب وضع `CHATGPT_ACCESS_TOKEN` بصورة خاصة في البيئة، ثم:

```bash
python scripts/verify_tool_environments.py --send-test --policy application
python scripts/verify_tool_environments.py --send-test --policy hybrid --native-compute
```

كل أمر ينشئ محادثة حقيقية ويرسل رسالتين عند نجاح استدعاء الأداة. لا يطبع التوكن أو المسارات الخاصة أو محتوى الملفات أو معرف المحادثة. يستخدم السكربت محرك البروكسي مباشرة؛ اختبارات HTTP وSSE المستقلة موجودة في حزمة الاختبارات.
